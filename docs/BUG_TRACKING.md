# Bug Tracking Guide

The team should use GitHub Issues for bug tracking.

## Where to report bugs

Open the repository on GitHub and use:

```text
Issues > New issue > Bug report
```

## What to include

Each bug report should include:

- Short title
- Feature area, such as Search, Gallery, Journal, Live Chat, Admin, Auth, Database, or Deployment
- Steps to reproduce
- Expected result
- Actual result
- Screenshot or terminal output when possible
- Severity: low, medium, high, or blocker

## Labels to use

Recommended labels:

```text
bug
frontend
backend
database
deployment
auth
live-chat
admin
needs-review
```

## Verification rule

For every feature marked as complete, someone who did not implement that feature should test it and open an issue for any problem found.

## Serious bugs

For serious bugs, assign a team member and add time for bug fixing in the project schedule.
